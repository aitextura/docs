## How it works

A new version is created **every time you click Save** on any tab of the AI Employee's settings. A version captures the **entire** configuration, not just the tab you changed.

| Rule | Description |
|---|---|
| **No autosave** | A version appears only when you act -- when you click Save |
| **Full snapshot** | Each version includes all tabs: [Persona](/en/guides/persona), [Knowledge Base](/en/guides/knowledge), [FAQ](/en/guides/self-learning), [Talents](/en/guides/talents), Channel, [Quick Answers](/en/guides/quick-answers), [Profiles](/en/guides/profiles), [Working Hours](/en/guides/working-hours), [Auto Follow-up](/en/guides/auto-followup), [Notifications](/en/guides/notifications), [Advanced](/en/guides/additional-settings) |
| **No limit** | There's no limit on the number of versions -- the platform keeps the full history from the moment the AI Employee was created |
| **No partial rollback** | Restoring replaces the entire configuration, not a single tab |

<Tip>
  Think of each save as a checkpoint. Before making major changes, just click Save to capture the current working state.
</Tip>

## The Versions tab interface

Open the AI Employee you need and go to the **Versions** tab in the top navigation bar.

| Element | Description |
|---|---|
| **Version list** | All saves, sorted from newest to oldest |
| **Date and time** | The exact moment of each save (in your account's time zone) |
| **Version number** | A sequential number assigned automatically. Numbering starts at 1 -- the moment the AI Employee was created |
| **View** | Click a version to open the AI Employee's configuration as of that moment (read-only) |
| **Restore this version button** | Makes the selected version the current configuration |

## How to view the change history

<Steps>
  <Step title="Open the AI Employee">
    Go to the [AI Employees](/en/guides/ai-employees) section and select the AI Employee you need.
  </Step>
  <Step title="Go to the Versions tab">
    In the top bar, click the **Versions** tab. You'll see a list of all saved versions, newest at the top.
  </Step>
  <Step title="Open the version you want">
    Click the version you need -- a card opens with the configuration details as of that moment. Viewing is read-only, so you can't change anything by accident.
  </Step>
</Steps>

## How to restore a previous version

<Steps>
  <Step title="Go to the Versions tab">
    Open the AI Employee and click the **Versions** tab.
  </Step>
  <Step title="Find the version you need">
    Select a version in the list and click it. Review the parameters to make sure it's the right one.
  </Step>
  <Step title="Click Restore this version">
    Click **Restore this version** and confirm.
  </Step>
</Steps>

Once you confirm, the AI Employee's configuration is replaced with the selected version, and it immediately starts working with it.

<Warning>
  Restoring replaces the **entire** configuration -- all tabs at once. If you need to roll back only one parameter, view the version you need, find the value, and copy it into the current configuration manually.
</Warning>

<Note>
  Restoring **doesn't delete** intermediate entries. The full history is kept, and the restored configuration becomes a new (latest) entry in the history. You can always go back.
</Note>

## Real-world examples

<Accordion title="Rolling back after a bad change">
  You rewrote the system prompt in the [Persona](/en/guides/persona), and the AI Employee started giving off-topic replies. Instead of trying to remember the old text, open **Versions**, find a stable version, and restore it. The AI Employee immediately goes back to its previous behavior.
</Accordion>

<Accordion title="A checkpoint before an experiment">
  Before a major rework of the script, click **Save** to capture the current state. If the experiment fails, you can go back in a second.
</Accordion>

<Accordion title="Before-and-after comparison">
  The AI Employee's performance got worse, but you're not sure which change caused it. Open **Versions**, view the last few entries, and compare the configurations to find the cause.
</Accordion>

<Accordion title="Working as a team">
  If several people configure the same AI Employee, the version history helps you track who changed what and when.
</Accordion>

## FAQ

<Accordion title="Is there a limit on the number of versions?">
  No. The platform keeps the full history -- you can go back to the very first configuration from when the AI Employee was created.
</Accordion>

<Accordion title="Are versions created automatically?">
  No, there's no autosave. A new version is created only when you click **Save** on any settings tab.
</Accordion>

<Accordion title="What happens to the current configuration when I roll back?">
  It isn't lost. The system creates a new entry in the history -- the current state becomes another version. You can return to it at any time.
</Accordion>

<Accordion title="Can I roll back just one tab?">
  No, restoring replaces the entire configuration. If you need to change only one parameter, view the version you need, find the value, and copy it over manually.
</Accordion>

<Accordion title="Can I delete a version from the history?">
  No. All versions are kept permanently and can't be deleted. This is intentional -- so you can always return to any state.
</Accordion>

<Accordion title="I didn't change anything but clicked Save -- will that create a duplicate?">
  Yes, a new entry appears in the history even if nothing changed. That's fine -- you just get an extra checkpoint.
</Accordion>

## Best practice

<Note>
  **Save before experimenting.** Before major changes, click Save -- it takes a second but can save you hours of recovery.
</Note>

<Note>
  **Don't be afraid to experiment.** Versions are your safety net. Try something -- don't like it -- roll back.
</Note>

<Tip>
  **Agent live preview: `Show chat`.** Before saving another version, try the new behavior right in the editor -- the **Show chat** toggle at the top opens a built-in test chat on the right. This lets you debug the [Persona](/en/guides/persona) and [Talents](/en/guides/talents) before the change goes to production.
</Tip>
