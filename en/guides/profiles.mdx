Profiles are customer cards that the AI Employee fills in **automatically** during the conversation. No manual work is needed: while the employee talks with the customer, it extracts the data you need and writes it into a structured table.

You decide exactly what to collect. Name and language are collected by default. Everything else is fields you configure for your needs.

## Configuring profile fields

Open the AI Employee → **Profiles** tab. On this tab, you describe **which fields** of the customer profile the employee should fill in and **when** to do it. Fields are tied to a specific agent: different employees can collect different sets of data.

<Frame>
  <img src="/public/screenshots/38-agent-profiles.png" alt="The Profiles tab in agent settings: field list, types, and update mode" />
</Frame>

Each field you define here appears as a separate column in the shared **Profiles** section and is automatically attached to the metadata of every chat for this employee.

### Update mode

The first thing to choose is when the employee updates the profile.

| Mode | When it updates | When to use it |
|---|---|---|
| **Realtime** | After every customer message | When the employee needs to use the data right away — for example, to address the customer by name or account for preferences in the same conversation |
| **Scheduled** | On a schedule (for example, once every 24 hours) | When you need the data only for analytics and reporting |

When you choose scheduled mode, additional settings appear: interval, start hour, and time zone. You'll also see a token usage forecast — how much will be spent per day and per month.

<Tip>
  If you're not sure what to choose, use **scheduled updates once every 24 hours**. That's enough for most scenarios and saves a lot of budget compared to Realtime.
</Tip>

---

### Field types

Each field has a type that determines whether the employee can update its value.

| Type | Behavior | Example |
|---|---|---|
| **Variable** | Updates with every new mention | Language, preferences, status, current interest |
| **Constant** | Set once and never changes | Contract number, date of birth, customer type |

<Warning>
  A constant can't be changed after it's first filled in. If you're not sure, choose **Variable**.
</Warning>

---

### Field parameters

Each field has four parameters:

| Parameter | What to enter |
|---|---|
| **Name** | A clear field name: "Name," "Language," "Request status" |
| **Description** | An instruction for the AI — when and what to fill in. This is **the most important parameter** |
| **Key** | Generated automatically; no need to change it |
| **Type** | Variable or Constant |

<Warning>
  **The field description is what matters most.** Write it **from the customer's perspective**: not "when the customer states their language," but "the language I communicate in." The more precise the description, the better the employee understands when to fill in the field.

  Also specify the answer format. For example: "yes/no" or "choose one of: Russian, English, other." Without this, the employee may record arbitrary text that's hard to analyze.
</Warning>

### How to add a field

<Steps>
  <Step title="Open the Profiles tab">
    Go to the AI Employee's card and select the **Profiles** tab.
  </Step>
  <Step title="Add a new field">
    Click the button to add a new field.
  </Step>
  <Step title="Enter a name">
    Give it a clear name — for example, "Name," "Language," "Budget."
  </Step>
  <Step title="Fill in the description">
    Describe in detail, **from the customer's perspective**, when and what to fill in. Specify the answer format.
  </Step>
  <Step title="Choose a type">
    **Variable** — if the value can change. **Constant** — if it's set once.
  </Step>
  <Step title="Save">
    Repeat for each field you need. There's no limit on the number of fields.
  </Step>
</Steps>

<Tip>
  Add only the fields you really need — this improves filling accuracy and saves tokens.
</Tip>

| Name | Variable | My name |

## Profile fields and chat metadata

Fields configured on the agent's **Profiles** tab automatically go into the **metadata of every chat** for this employee. This means:

- In the **Profiles** section (left menu), you see these fields as table columns.
- In the Persona, you can reference these fields as variables — the employee will insert the values right into the conversation (see [Persona](/en/guides/persona)).
- In chats, the metadata is available via the chat actions menu → "Customer profile."

### Field types

| Field type in settings | Stored in metadata as | Example |
|---|---|---|
| Text (Variable) | Free text | `Name`, `City`, `Summary` |
| Text with answer format (Variable) | One of the defined options | `Language: Russian / English / other`, `Status: new / in progress / resolved` |
| Text (Constant) | A fixed value that doesn't change after it's first filled in | `Contract number`, `Date of birth` |
| Number (Variable) | A numeric value | `Budget`, `Number of guests` |
| Short description (Variable) | A few words or one sentence | `Complaint` (≤ 4 words), `Summary` (2 sentences) |

<Tip>
  The field type isn't set with an explicit selector but through **how you word the description** for the AI. In the description, specify the answer format — "choose one of: …," "record a number," "no more than four words" — and the employee will stick to that format when writing to the metadata.
</Tip>

## Profile analytics

The **Profiles** section in the platform's left menu is an analytics tool. It stores the filled-in cards of all customers across all employees.

<Frame>
  <img src="/public/screenshots/50-profiles.png" alt="The Profiles section: KPI tiles, view tabs, and data table" />
</Frame>

### KPI tiles

At the top of the page are four summary cards:

| Metric | What it shows |
|---|---|
| **Total profiles** | The total number of customers for all time |
| **Completeness** | The average percentage of filled fields — how fully the employee extracts data |
| **This week** | New profiles this week |
| **This month** | New profiles this month |

### View tabs

Above the table are tabs:

- **All data** — the standard view with all fields for all employees.
- **Saved views** — custom views with preconfigured filters, columns, and sorting. Handy when you have several analysis scenarios: "Hotel leads," "Complaints this week," "Requests in progress."

<Tip>
  Create your own view: set up filters and column order for the task at hand, then save it — next time you'll open it in one click.
</Tip>

### Profiles table

Each row is one customer. Standard columns: profile, employee, Chat ID, name, language, summary. Plus all the custom fields you configured on the **Profiles** tab of each agent (for example, `business industry`, `purpose of purchasing the service`).

<Frame>
  <img src="/public/screenshots/81-profiles-detail.png" alt="Detailed customer profile view: all fields, history, link to the chat" />
</Frame>

Table features:

- **Filter by employee** — view data for a single employee or branch
- **Search** by name, field contents, or any text
- **Go to chat** — click the Chat ID to open the full conversation history
- **Column management** — hide columns you don't need
- **Drag-and-drop column order** (new in v2.1.0) — drag column headers with your mouse to arrange them the way that works for you. The new order is saved in the current view
- **Display modes** — switch between **Cards** and **Table** views

<Tip>
  If a field isn't being filled in, check its description in the employee's settings. Most likely, the AI doesn't understand when exactly to record the data.
</Tip>

## Using profiles in the Persona

You can use profile data right in the employee's instructions — through **profile variables** in the [Persona](/en/guides/persona) section. For example, if the customer's name is known, the employee can address them personally during the conversation.

This lets you create truly personalized communication: account for preferences, adapt the style, and offer relevant solutions based on the collected data.

## FAQ

<Accordion title="Is Realtime more expensive than scheduled?">
  Yes, significantly. Realtime updates the profile after every message and uses noticeably more tokens. Scheduled mode processes data in batches, which is more economical.
</Accordion>

<Accordion title="Can I change a constant's value?">
  No. That's the whole point of the Constant type — the value is set once and doesn't change. If you're not sure, choose Variable.
</Accordion>

<Accordion title="Are profiles shared across all employees?">
  No, each employee keeps its own customer profiles.
</Accordion>

<Accordion title="How many fields can I add?">
  There's no limit, but add only the fields you really need — this improves accuracy and reduces token usage.
</Accordion>
