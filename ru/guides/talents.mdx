Таланты превращают вашего ИИ-сотрудника из хорошего собеседника в полноценного помощника, который не просто отвечает на вопросы, а выполняет реальные действия: бронирует номера, создаёт сделки в CRM, ищет информацию в базе, отправляет письма, формирует документы.

**Без талантов сотрудник умеет только разговаривать. С талантами — он работает.**

<Note>
  **«Талант» = MCP-инструмент.** Не путайте с **каналом** ([Каналы](/ru/channels/index)). Канал — это источник входящих сообщений (Telegram, Wazzup, Bitrix24-канал), а талант — это **инструмент действия** (создать сделку, проверить номер в PMS, найти товар, отправить письмо). Один и тот же сервис может быть и каналом, и талантом — это два независимых подключения. Подробнее в разделе [Bitrix24 — два пути подключения](#bitrix24-2-puti-podklyucheniya) ниже.
</Note>

## <a id="bitrix24-2-puti-podklyucheniya"></a>Bitrix24 — два пути подключения

В платформе Bitrix24 встречается **дважды** — как талант и как канал ([/ru/channels/bittrix24](/ru/channels/bittrix24)). Это **два независимых подключения**:

| Тип | Где | Зачем |
|---|---|---|
| **Канал** | [Канал](/ru/channels/bittrix24) — REST webhook URL | Принимать сообщения из Открытых линий Bitrix24 в чаты AI TEXTURA |
| **Талант** | Таланты → Bitrix24 | Выполнять CRM-операции из ответа агента: создание лидов и сделок, поиск контактов, постановка задач, назначение ответственных |

Их **можно (и часто нужно) подключать одновременно**: канал — чтобы получать сообщения, талант — чтобы делать CRM-действия в ответ.

### Подключение таланта Bitrix24

Кликните по карточке `Bitrix24` в каталоге талантов. В модале — две вкладки:

<Tabs>
  <Tab title="Подключённый канал">
    «Используйте авторизацию уже подключённого канала Битрикс24. Самый простой способ.»

    1. Выберите подключённый канал из выпадающего списка.
    2. Нажмите **Далее** — талант получит права из канала.
  </Tab>
  <Tab title="Webhook">
    Создайте отдельный входящий webhook в Bitrix24. Этот вариант полезен, когда канал не используется или нужен изолированный набор прав.

    <Steps>
      <Step title="В Bitrix24 откройте раздел разработчиков">
        `Приложения → Разработчикам → Другое → Входящий вебхук`
      </Step>
      <Step title="Выберите права доступа">
        Отметьте все необходимые права:

        - **CRM** (`crm`)
        - **Пользователи** (`user`)
        - **Задачи** (`task`)
        - **Чат и уведомления** (`im`)
        - **Создание и управление Чат-ботами** (`imbot`)
        - **Открытые линии** (`imopenlines`)
      </Step>
      <Step title="Сохраните и скопируйте URL вебхука">
        Bitrix24 покажет webhook URL вида `https://your-portal.bitrix24.ru/rest/1/abcdef0123456/`.
      </Step>
      <Step title="Вставьте URL в AI TEXTURA">
        Вернитесь в модал таланта Bitrix24 и вставьте URL в соответствующее поле. Нажмите **Подключить**.
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Tip>
  Если вы уже подключили [канал Bitrix24](/ru/channels/bittrix24) — выберите вкладку **Подключённый канал**, это сэкономит шаги. Webhook-вариант нужен, когда канал не используется или права канала недостаточны.
</Tip>

## Как подключить любой талант

  <Step title="Откройте раздел Таланты">

## Несколько экземпляров одного таланта

Вы можете подключить **один и тот же талант несколько раз** с разными настройками. Это полезно, когда:

- У вас **несколько отелей** — для каждого свой экземпляр Travelline / Bnovo / MEWS со своим Hotel ID
- У вас **несколько сотрудников** — для каждого свой Google Calendar
- Нужны **разные конфигурации** одного сервиса — например, два MySQL для разных БД

Каждому экземпляру дайте понятное название, чтобы сотрудник и вы могли их различать: «Бронирование — Отель Приморский» / «Бронирование — Отель Горный».

## <a id="sozdanie-svoego-mcp-talanta"></a>Создание своего таланта (Custom MCP)

Если в каталоге нет нужной интеграции — подключите **свой MCP-сервер**. AI TEXTURA поддерживает протокол **Model Context Protocol (MCP)**: любой совместимый сервер можно подключить как талант.

<Frame><img src="/public/screenshots/22-talent-create-custom.png" alt="Создание custom MCP-таланта — выбор типа сервера, авторизации и заголовков" /></Frame>

### Параметры формы «Создать талант»

| Поле | Описание |
|---|---|
| **Тип сервера** | **SSE** (Server-Sent Events) или **Streamable HTTP** — зависит от реализации вашего MCP-сервера |
| **Server URL** | Адрес вашего MCP-сервера (HTTPS обязателен) |
| **Авторизация** | Один из режимов: **Без** / **Bearer Token** / **API Key** / **Basic Auth** |
| **HTTP заголовки** | Произвольные ключ-значение пары для каждого запроса (например, `X-Tenant-Id: ...`) |
| **«Я доверяю этому серверу»** | Обязательный чекбокс — подтверждение, что сервер контролируется вами или проверенной стороной |

### Режимы авторизации

| Режим | Когда использовать |
|---|---|
| **Без** | MCP-сервер не требует авторизации (например, локальная разработка или внутренняя сеть) |
| **Bearer Token** | Токен передаётся в заголовке `Authorization: Bearer <token>` |
| **API Key** | Произвольное имя заголовка + ключ (например, `X-API-Key: <key>`) |
| **Basic Auth** | Логин/пароль, кодируются в `Authorization: Basic <base64>` |

<Warning>
  **Чекбокс «Я доверяю этому серверу»** обязателен. Платформа предупреждает: подключая неверифицированный MCP-сервер, вы передаёте ему весь контекст диалога с клиентом и делегируете действия от имени агента. Не подключайте сторонние серверы, которым не доверяете.
</Warning>

### Пошаговая настройка custom MCP

<Steps>
  <Step title="Подготовьте MCP-сервер">
    Убедитесь, что ваш сервер реализует MCP по SSE или Streamable HTTP, доступен по HTTPS и валидирует входящие запросы.
  </Step>
  <Step title="Нажмите «Создать талант»">
    Кнопка находится в верхней части вкладки **Таланты**.
  </Step>
  <Step title="Выберите тип сервера">
    **SSE** или **Streamable HTTP** — соответственно реализации.
  </Step>
  <Step title="Укажите URL и авторизацию">
    Введите Server URL, выберите режим авторизации и заполните соответствующие поля.
  </Step>
  <Step title="Добавьте заголовки (опционально)">
    Если сервер требует кастомные HTTP-заголовки — добавьте их в виде ключ-значение пар.
  </Step>
  <Step title="Подтвердите доверие и сохраните">
    Поставьте галочку **«Я доверяю этому серверу»** и нажмите **Сохранить**. Талант появится в каталоге.
  </Step>
</Steps>

<Tip>
  Custom MCP подходит для интеграции с внутренними системами компании (внутренний CRM, ERP, биллинг) и нестандартной логики, которой нет в готовых талантах. Для простых HTTP-запросов проще использовать готовый талант **HTTP / Webhook**.
</Tip>

## Связь с Персоной — критически важно

<Warning>
  Подключить талант — это половина дела. **Вторая половина — описать его в [Персоне](/ru/guides/persona) сотрудника.** Без этого сотрудник может не понять, когда применять талант, или вовсе «забыть» о нём.
</Warning>

В разделе [Персона](/ru/guides/persona) пропишите конкретные инструкции для каждого подключённого таланта:

> Когда гость спрашивает о доступности номеров на конкретные даты — используй Travelline для проверки. Покажи доступные варианты с ценами.

> Когда клиент готов оформить заказ — создай сделку в Bitrix24 через талант, заполни поля «Имя», «Телефон» и «Сумма» из контекста диалога.

> Когда клиент просит счёт — создай платёжную ссылку через Stripe и пришли её клиенту.

Чем точнее описание в Персоне — тем уместнее сотрудник применяет таланты.

## На что обратить внимание

<Steps>
  <Step title="Подготовьте данные заранее">
    Hotel ID, ключи доступа, регион, OAuth-аккаунты — соберите всё до начала подключения.
  </Step>
  <Step title="Тестируйте сразу">
    После подключения откройте `Показать чат` и проверьте сценарий, в котором сотрудник должен использовать талант.
  </Step>
  <Step title="Следите за авторизацией">
    OAuth-токены могут истекать; webhook'и в CRM могут быть отозваны. Проверяйте вкладку **Подключённые**.
  </Step>
  <Step title="Различайте канал и талант">
    Сообщение приходит — это канал. Сотрудник делает действие — это талант. Не подключайте талант там, где нужен канал, и наоборот.
  </Step>
  <Step title="Опишите в Персоне">
    Без чёткой инструкции в Персоне сотрудник может не использовать талант. Прописывайте конкретные ситуации.
  </Step>
</Steps>

## Частые вопросы

<AccordionGroup>
  <Accordion title="Чем талант отличается от канала?">
    Канал — источник входящих сообщений (Telegram, Wazzup, Bitrix24-канал). Талант — инструмент действия, который сотрудник вызывает из ответа (создать сделку в CRM, проверить номер в PMS, отправить email). Bitrix24 и amoCRM встречаются и там и там — это **два разных подключения**: канал для разговора, талант для CRM-операций. Подробности — [Каналы](/ru/channels/index) и [Bitrix24](/ru/channels/bittrix24).
  </Accordion>
  <Accordion title="Что такое MCP?">
    Model Context Protocol — открытый стандарт описания инструментов для языковых моделей. Большинство современных AI-инструментов (включая каталог AI TEXTURA) реализованы как MCP-серверы. Это даёт возможность подключать **свои** серверы по тому же протоколу — см. [Создание своего таланта](#sozdanie-svoego-mcp-talanta).
  </Accordion>
  <Accordion title="Сколько талантов можно подключить к одному сотруднику?">
    Технических ограничений нет. Но чем больше талантов, тем важнее чётко описать в [Персоне](/ru/guides/persona), когда какой использовать.
  </Accordion>
  <Accordion title="Можно ли подключить один талант несколько раз?">
    Да. Это полезно для нескольких экземпляров с разными настройками — например, два Travelline для двух отелей.
  </Accordion>
  <Accordion title="Талант подключён, но сотрудник его не использует. Что делать?">
    Скорее всего, в [Персоне](/ru/guides/persona) нет инструкции. Добавьте правило: «Когда клиент спрашивает о [ситуация] — используй [название таланта]». Затем протестируйте через `Показать чат`.
  </Accordion>
  <Accordion title="Что будет, если внешний сервис недоступен?">
    Сотрудник сообщит клиенту, что не может выполнить действие, и предложит альтернативу. Сам сотрудник продолжит работать — просто без конкретного таланта.
  </Accordion>
  <Accordion title="Можно ли подключить талант, которого нет в каталоге?">
    Да. Используйте кнопку **+ Создать талант** для подключения собственного MCP-сервера, либо универсальный талант **HTTP / Webhook** для отправки произвольных HTTP-запросов.
  </Accordion>
  <Accordion title="Безопасно ли подключать custom MCP?">
    Подключайте только серверы, которым вы доверяете. Через MCP сервер получает контекст диалога и может действовать от имени агента. Чекбокс **«Я доверяю этому серверу»** обязателен — это явное подтверждение ответственности.
  </Accordion>
  <Accordion title="Зачем подключать Bitrix24 и каналом, и талантом?">
    Канал нужен, чтобы сообщения из Открытых линий Bitrix24 попадали в чаты AI TEXTURA. Талант нужен, чтобы сотрудник мог делать CRM-операции (создавать лиды, сделки, задачи) в ответ. Это два разных слоя интеграции — и обычно нужны оба.
  </Accordion>
  <Accordion title="Где взять PMS-параметры?">
    В личном кабинете соответствующей PMS. Подробности по конкретным системам — [FAQ — PMS-интеграции](/ru/faq/pms-integrations). По AI TEXTURA-нюансам можно обратиться в [Поддержку](/ru/guides/support).
  </Accordion>
  <Accordion title="Нужно ли платить за таланты?">
    Часть талантов работает без доплат в рамках тарифа. Некоторые интеграции требуют подписки на сторонний сервис (Google Workspace, Notion, Stripe и т.д.) — это отдельные расходы у соответствующих провайдеров.
  </Accordion>
</AccordionGroup>
